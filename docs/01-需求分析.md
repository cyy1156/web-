# 需求分析

> 项目定位：课程设计 / 演示项目，对标上海理工大学《全日制本科生选课办法》。
> 交付目标：主流程跑通 + 界面可用 + 规则讲得清。不追求真实上线级别的运维能力。
> 声明：本项目为教学演示项目，与上海理工大学官方系统无关，不使用任何真实学生数据。

## 1. 背景与目标

高校选课系统是教务管理中最典型的"高并发 + 强规则"场景：开放瞬间大量学生集中抢课，系统必须在保证数据一致的前提下，实时拦截容量已满、学分超限、时间冲突、先修未修等非法请求。

本项目复刻该校的三轮选课节奏，重点解决三件事：

1. **不超卖**：教学班容量在任何并发下都不可被突破
2. **规则可解释**：每个失败都给出学生看得懂的中文原因，而不是错误码
3. **体验可用**：选课大厅的余量、冲突、学分进度实时可见

## 2. 角色与权限

| 角色 | 说明 | 主要权限 |
|---|---|---|
| 学生 STUDENT | 在校本科生 | 浏览开课目录、选课、退课、查看课表、培养计划、学分进度 |
| 管理员 ADMIN | 教务处教务员 | 配置选课轮次、维护教学班、停开班级、查看统计看板、导出名单 |

教师仅作为教学班的属性字段（姓名、职称）存在，不提供登录。此裁剪可省去一整套角色权限与课表编排流程，符合课程设计周期。

## 3. 功能需求

### 3.1 学生端

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| S1 | 登录 | 学号 + 密码，JWT 鉴权，7 天有效 | P0 |
| S2 | 选课大厅 | 左筛选、中列表、右已选清单三栏；课程卡显示余量与三色进度条 | P0 |
| S3 | 选课 | 校验轮次、重复、容量、学分、冲突、先修、跨年级，失败给中文原因 | P0 |
| S4 | 退课 | 轮次允许且非必修课时可退，退后名额立即释放 | P0 |
| S5 | 我的课表 | 周一至周五 × 12 节网格，同课程同色，支持周次过滤 | P0 |
| S6 | 学分进度 | 环形图显示已选/上限，超限变红并禁用确认 | P0 |
| S7 | 培养计划 | 按学期展示应修课程与完成状态 | P1 |
| S8 | 余量实时刷新 | 3 秒轮询可见教学班，页面隐藏时暂停 | P0 |

### 3.2 管理端

| 编号 | 功能 | 说明 | 优先级 |
|---|---|---|---|
| A1 | 数据看板 | 选课人次、平均门数、满班数、各学院选课率、热门课程 TOP10 | P0 |
| A2 | 轮次配置 | 开启/关闭三轮，设置起止时间与是否允许退课 | P0 |
| A3 | 教学班管理 | 新增、编辑、停开，查看实时选课人数 | P0 |
| A4 | 名单导出 | 按教学班导出 CSV（Excel 可直接打开） | P1 |
| A5 | 名单锁定 | 第三轮结束后锁定，学生端全部置灰 | P0 |

## 4. 关键业务规则

### 4.1 三轮选课

| 轮次 | 时间 | 业务含义 |
|---|---|---|
| 第一轮 海选 | 第 12 周 | 按指导性修读意见选课，先到先得、额满为止 |
| 第二轮 补选 | 第 15 周 | 依第一轮结果取消或合并教学班，释放资源 |
| 第三轮 退改选 | 开课第 3 周 | 试听两周后自主调整，结束后名单锁定 |

### 4.2 学分约束

- 下限 15.0 学分
- 上限一般 30.0 学分，且含重修学分
- 不超过培养计划学期学分的 ±30%

### 4.3 校验顺序

```
轮次窗口 → 重复选课 → 容量 → 学分 → 时间冲突 → 先修 → 跨年级
```

顺序按"代价从低到高"排列，热点路径只保留两次索引查询加一次原子更新。

### 4.4 错误码

| code | 含义 |
|---|---|
| 40001 | 不在选课窗口 |
| 40002 | 容量已满 |
| 40003 | 时间冲突 |
| 40004 | 先修未通过 |
| 40005 | 学分超限 |
| 40006 | 已选过 / 重复提交 |
| 40007 | 跨年级越级 |
| 40008 | 该课程不可退 |
| 40009 | 请求过频 |
| 40010 | 名单已锁定 |

## 5. 非功能需求

| 项 | 目标 | 达成方式 |
|---|---|---|
| 并发正确性 | 800 并发抢 100 容量，零超卖 | InnoDB 行锁 + 条件 UPDATE + CHECK 约束 |
| 响应时间 | 选课接口 P99 < 300ms | 热点路径仅 3 次 SQL，全部走主键/唯一索引 |
| 幂等 | 重复提交不产生第二条记录 | `Idempotency-Key` + `enrollment_log` 唯一索引 |
| 一致性 | `selected_count` 与实际记录数一致 | 同事务写入 + 对账脚本 |
| 可审计 | 谁在何时选了哪个班、失败原因 | `enrollment_log` 全量留痕 |
| 合规 | 无真实个人信息 | 学生数据全部脚本生成 |

## 6. 范围边界

**做**：登录、选课、退课、课表、学分进度、三轮配置、教学班管理、看板。

**不做**：教师端、成绩管理、学费、消息通知、跨校区、研究生选课、移动端适配、微服务化。

## 7. 验收标准

| 场景 | 期望 |
|---|---|
| 两人抢最后 1 个名额 | 一个成功、一个 40002，`selected_count` 不超过 capacity |
| 学分超上限 | 返回 40005 并给出具体数字 |
| 时间冲突 | 返回 40003 并指出冲突课程与节次 |
| 先修未通过 | 返回 40004 并指出缺哪门先修课 |
| 轮次关闭 | 学生端按钮全灰，接口返回 40001 |
| 名单锁定 | 接口返回 40010，所有写操作失效 |
