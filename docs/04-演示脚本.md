# 演示脚本（答辩/验收 5 分钟）

## 0. 准备

```bash
# 1. 初始化数据库
mysql -uroot -e "DROP DATABASE IF EXISTS course_selection; CREATE DATABASE course_selection DEFAULT CHARSET utf8mb4;"
mysql -uroot course_selection < db/schema.sql
python scripts/gen_seed.py --students 2000 --classes 400
mysql -uroot course_selection < db/seed.sql

# 2. 启动后端
cd backend && mvn spring-boot:run

# 3. 启动前端
cd frontend && npm run dev
```

账号：学生 `20240001 / 123456`，管理员 `admin / 123456`。

## 1. 开场（30 秒）

> 这是一个对标上海理工大学教务选课系统的教学演示项目。选课系统真正的难点不是页面，而是开放瞬间的并发与规则校验。我重点做了三件事：容量绝不超卖、每个失败都能解释、余量与冲突实时可见。

## 2. 学生端主流程（2 分钟）

1. 登录 `20240001`，进入选课大厅
2. 左侧筛选"必修 + 仅看有余量"，中间列表按余量排序
3. 讲解右侧：已选 5 门、18.5 学分、环形进度
4. 选一门有余量的课 → 右侧清单插入动画，学分数字滚动
5. 切到"我的课表"，展示彩色色块与同课同色
6. 切到"培养计划"，展示按学期的完成状态

## 3. 四个拦截场景（1.5 分钟）

| 操作 | 期望提示 |
|---|---|
| 选一门与已选课程同时间段的课 | 与《大学物理》周三 3-4 节冲突 |
| 选一门会突破 30 学分的课 | 超出学期学分上限（已选 28.5 / 30.0） |
| 选一门先修课未通过的课 | 需先修《高等数学A(1)》且成绩合格 |
| 选一门低年级不能选的高年级课 | 低年级不可选修高年级课程 |

> 关键点：所有提示都是中文业务语言，没有把 `40003` 这种错误码丢给学生。

## 4. 并发不超卖（1 分钟）

```bash
# 建议先造一个容量为 1 的观察用教学班（时间位图置 0，排除冲突干扰）
python scripts/concurrent_test.py --class-id 401 --threads 30
```

实测输出（容量 1，30 名学生同时发出请求）：

```text
[4/4] 耗时 0.28s
容量            : 1
成功选课        : 1
返回 40002      : 28
其他失败        : 1        # 40007 低年级不可跨选，属正常业务拦截
selected_count  : 1
实际记录数      : 1
结论            : [PASS] 无超卖，数据一致
```

脚本还会对账：`selected_count == enrollment 实际记录数`、`selected_count <= capacity`、成功数 == 计数增量，三项同时成立才打印 `[PASS]`。

> 原理：容量扣减只有一条带条件的 UPDATE，`WHERE selected_count < capacity`，InnoDB 行锁让同一教学班的并发串行化，影响行数为 0 就直接回滚。
>
> 注意：失败日志必须写在事务回滚之后（`EnrollmentService` 用 `TransactionTemplate` 显式控制边界）。若在持有行锁的事务里用 `REQUIRES_NEW` 另开连接写日志，高并发下会占满连接池并互相等待，表现为接口集体超时。

## 5. 管理端（1 分钟）

1. 用 `admin` 登录，看板展示选课人次、满班数、各学院选课率、热门课程 TOP10
2. "轮次配置"关闭第一轮 → 学生端按钮全灰，接口返回 40001
3. "教学班管理"把某班容量从 120 改成 60（不得小于已选人数）
4. 导出某个教学班的名单 CSV（带 BOM，Excel 直接打开不乱码）

## 6. 收尾（30 秒）

> 整个系统 16 张表、22 个接口、7 个页面。核心正确性靠三条：条件 UPDATE、唯一索引生成列、时间位图。工期 15 天，技术栈是 Spring Boot 3 + Vue 3，没有引入 Redis 和消息队列——因为课程设计规模下，单机 MySQL 的行锁已经足够，引入中间件反而增加出错面。

## 7. 常见追问

| 问题 | 回答 |
|---|---|
| 为什么不用 Redis 预扣减？ | 会引入缓存与 DB 的一致性问题，需要补偿逻辑；单机 MySQL 800 并发已能满足，Redis 留作扩展点 |
| 超卖怎么彻底避免？ | DB 条件 UPDATE 是最终防线，CHECK 约束兜底，任何路径都绕不过 |
| 退课后能重选吗？ | 能，`status_flag` 生成列在退课时变 NULL，唯一索引失效 |
| 时间冲突怎么判？ | 一个 BIGINT 存 60 个节次位，AND 运算一次出结果 |
| 幂等怎么做的？ | 请求头带 UUID，落 `enrollment_log` 唯一索引，重放直接返回首次结果 |
| 名单锁定后怎么处理？ | `semester.locked = 1`，所有写接口前置校验返回 40010 |
