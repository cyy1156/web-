# 部署指南：GitHub 上传 + 云服务器上线

面向单台 Linux 云服务器（Ubuntu 22.04 / 24.04，2 核 2G 起）。架构：

```text
浏览器 ──> Nginx :80 ──┬── /            -> /var/www/course-selection（Vue 构建产物）
                       └── /api/        -> 127.0.0.1:8080（Spring Boot，systemd 托管）
                                                  └──> MySQL 8（本机 3306）
```

部署形态说明：前端是 SPA、后端是同源 `/api`，所以**一次 Nginx 反代就够了**，不需要给后端单独开公网端口，也就不存在跨域问题。

## 一、上传到 GitHub

仓库已经在本地初始化并完成首次提交，`.gitignore` 已排除 `node_modules/`（约 390 MB）、`target/`、`dist/`、日志与浏览器录制目录 `shots/`。

```bash
# 在 GitHub 新建空仓库（不要勾选 README），然后：
cd d:/web开发
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

认证二选一：

- **HTTPS + Token**：密码框粘贴 Personal Access Token（`repo` 权限），不是账号密码；
- **SSH**：`ssh-keygen -t ed25519 -C "you@example.com"`，把 `~/.ssh/id_ed25519.pub` 加到 GitHub → Settings → SSH keys，remote 用 `git@github.com:<用户名>/<仓库名>.git`。

提交前自查：

```bash
git status --short          # 不应出现 node_modules、target、dist
git count-objects -vH       # 仓库体积应在几 MB 内（seed.sql 约 1.1 MB）
```

## 二、服务器准备

```bash
sudo apt update
sudo apt install -y openjdk-17-jre-headless nginx mysql-server
java -version        # 17.x
```

创建运行用户与目录：

```bash
sudo useradd -r -s /usr/sbin/nologin course
sudo mkdir -p /opt/course-selection/logs /etc/course-selection /var/www/course-selection
sudo chown -R course:course /opt/course-selection
sudo chmod 600 /etc/course-selection/env 2>/dev/null || true
```

安全组/防火墙只放行 **22、80**（后续上 HTTPS 再加 443）。`8080`、`3306` **不要**对外开放。

## 三、初始化数据库

在本地把两个 SQL 传到服务器，然后在服务器导入：

```bash
# 本地执行
scp db/schema.sql db/seed.sql root@<服务器IP>:/tmp/
```

```bash
# 服务器执行
sudo mysql -e "CREATE DATABASE IF NOT EXISTS course_selection DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"
sudo mysql course_selection < /tmp/schema.sql
sudo mysql course_selection < /tmp/seed.sql

# 建一个只读写业务表的应用账号（不给 DDL）
sudo mysql -e "
CREATE USER IF NOT EXISTS 'course_sel'@'localhost' IDENTIFIED BY '换成强密码';
GRANT SELECT, INSERT, UPDATE, DELETE ON course_selection.* TO 'course_sel'@'localhost';
FLUSH PRIVILEGES;"
```

校验：

```bash
sudo mysql -e "SELECT COUNT(*) AS students FROM course_selection.student;
               SELECT COUNT(*) AS classes FROM course_selection.teaching_class;"
# 期望 2000 与 400
```

> `seed.sql` 里的密码哈希对应演示密码 `123456`，上线演示没问题；若要长期公开，改掉管理员密码或不要导入种子学生。

## 四、后端部署

### 1. 本地打包

```bash
cd d:/web开发/backend
mvn clean package -DskipTests      # 产物 target/course-selection-1.0.0.jar
```

> 服务器只有 JRE 就能跑；不要把 `target/` 提交到仓库，直接把 jar 传上去。

### 2. 上传并配置环境变量

```bash
scp backend/target/course-selection-1.0.0.jar root@<服务器IP>:/opt/course-selection/app.jar
```

```bash
# 服务器执行
sudo tee /etc/course-selection/env > /dev/null <<'EOF'
DB_URL=jdbc:mysql://127.0.0.1:3306/course_selection?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
DB_USERNAME=course_sel
DB_PASSWORD=换成强密码
JWT_SECRET=换成b64随机串
LOG_PATH=/opt/course-selection/logs
EOF

sudo chmod 600 /etc/course-selection/env
openssl rand -base64 48        # 生成的串填到 JWT_SECRET
```

`JWT_SECRET` 缺失会启动失败（`application-prod.yml` 故意不给默认值），这是为了避免线上误用仓库里的演示密钥。

### 3. 安装 systemd 服务

```bash
sudo cp deploy/course-selection.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now course-selection
sudo systemctl status course-selection --no-pager
```

自检：

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/api/semesters/current
# 401 就是正常的：接口在跑，只是没带 token
sudo tail -n 50 /opt/course-selection/logs/stderr.log
```

## 五、前端部署

```bash
cd d:/web开发/frontend
npm ci && npm run build            # 产物 dist/，baseURL 走相对路径 /api
```

上传静态文件（`dist/` 里的内容直接铺到网站根目录）：

```bash
scp -r frontend/dist/* root@<服务器IP>:/var/www/course-selection/
sudo chown -R www-data:www-data /var/www/course-selection
```

配置 Nginx：

```bash
sudo cp deploy/nginx.conf /etc/nginx/conf.d/course-selection.conf
sudo rm -f /etc/nginx/sites-enabled/default    # 避免默认站点抢占 80
sudo nginx -t && sudo systemctl reload nginx
```

访问 `http://<服务器IP>/`，用 `20240001 / 123456` 或 `admin / 123456` 登录。刷新任意子路由（如 `/timetable`）都应正常，`try_files` 已处理 history 回退。

## 七、日常更新

```bash
# 本地
mvn -f backend/pom.xml clean package -DskipTests
npm --prefix frontend run build

# 上传
scp backend/target/course-selection-1.0.0.jar root@<IP>:/opt/course-selection/app.jar
scp -r frontend/dist/* root@<IP>:/var/www/course-selection/

# 服务器
sudo systemctl restart course-selection
sudo systemctl reload nginx
```

建议用 GitHub 拉代码在服务器构建的替代方案（服务器需装 Maven + Node）：

```bash
git clone https://github.com/<用户名>/<仓库名>.git /srv/course-selection
cd /srv/course-selection && mvn -f backend/pom.xml clean package -DskipTests
```

2G 内存的机器上 `mvn package` 容易 OOM，实际更推荐"本地构建 + scp 产物"。

与指南的差异（Linux 发行版相关）：

- 宝塔托管的 Nginx **不能用 `systemctl reload nginx`**（服务名不是 nginx），要用 `sudo /etc/init.d/nginx reload`；
- 包管理器是 `dnf`（Alibaba Cloud Linux 3），不是 `apt`；
- MySQL 面板里记录的 root 密码可能与实际不一致，建库时以实际能登录的密码为准。

## 十、常见问题

| 现象 | 排查 |
|---|---|
| 502 Bad Gateway | 后端没起来：`systemctl status course-selection`、看 `logs/stderr.log`；多半是 `JWT_SECRET` 未设置或数据库密码错 |
| 页面能开但接口全 401 | token 过期（prod 配置 24 小时），重新登录；或 Nginx 未转发 `Authorization`（本配置默认透传） |
| 登录报"账号或密码错误" | 种子数据没导入，或导入了别的库；核对 `SELECT COUNT(*) FROM sys_user` |
| 刷新子路由 404 | Nginx 缺 `try_files $uri $uri/ /index.html` |
| MySQL 连接被拒 | 账号只授权了 `localhost`，`DB_URL` 里别写公网 IP；确认 `bind-address` 未被改 |
| 导出文件乱码 | 导出为带 BOM 的 UTF-8 CSV，用 Excel 直接双击打开即可 |
